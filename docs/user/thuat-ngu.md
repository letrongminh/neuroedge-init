## 4. Product terminology

| Term | Meaning | Further reading |
|:---|:---|:---|
| **Gate** | Safety policy in YAML for a physical action: `evaluate` criteria, `allow_when` conditions, `on_block` behavior when blocked, `budget` limits | `docs/spec/core_contracts.md` Appendix B |
| **Verdict** | Evaluation result of a gate: `ALLOW` or `BLOCK` with `reason` | `python/neuroedge/engine/verdict.py` |
| **Gate inheritance (`extends`)** | Child gate reuses parent gate and **may only narrow** (five principles B.5) | `docs/spec/core_contracts.md` Appendix B.5 |
| **Starter gate library** | Seven parent gates in `gates/home/` to `extends`: `door-lock`, `light`, `valve`, `siren`, `hvac`, `camera`, `motor`. Locked in `digests.lock`; each gate has loosening counterexamples rejected by `gate lint`; all numerical criteria feedable from real `analog.in` channel | `docs/user/huong-dan.md` §4.1 · TSK-I2b-03 |
| **Open platform · Extension SDK** | Q-67: third parties connect NeuroEdge to new products without modifying core. Extension SDK (`neuroedge.sdk`) is a set of extension points for plugins, with separate versioning and stability commitments | `docs/architecture/vi/16-ecosystem-landscape.md` §4 · RFC-0016 |
| **Plugin · extension point** | External Python package declared via entry points, falling into one of six categories: **bridge** (incoming commands from external systems), **fact source** (incoming facts), **actuator** (including remote), **board**, **template**, **exporter**. Loaded only when explicitly enabled | RFC-0016 |
| **`neuroedge.guard`** | Standalone safety core: gate → token → envelope → trace for any program, without requiring `agent.toml` | RFC-0016 · TSK-I2c-07 |
| **`bridge:<id>`** | `source` value of a tool call entering via a bridge plugin; core assigns by plugin name, caller cannot self-declare | RFC-0017 |
| **Remote actuator · self-disable level** | Actuator not on pins of machine running NeuroEdge (Home Assistant entity, Matter device…), driven by `neuroedge.actuators` plugin; appears to agent as a named `digital.out` pin declared in `[actuators.<name>]`. Self-disable level specifies how it returns to safe state upon timeout or communication loss; non-reversible actions require self-disabling hardware | RFC-0018 · `docs/spec/extension_sdk.md` §7 |
| **L0 · L1 · L2 · L3 (self-disable levels)** | Who resets remote actuator to `off` (becomes "to `safe_state`" under conditional safety RFC, Q-72) when NeuroEdge is unreachable: L0 nobody · L1 NeuroEdge process (host timer) · L2 on-device timer (`on` always carries `duration_ms`) · L3 on-device lease (NeuroEdge renews, stopping renewal ⇒ off). **Distinct from** Action CI L1–L3 (FR-CI-LVL) | RFC-0018 §3d |
| **Turn-off debt** | An active turn-on command **issued by NeuroEdge** to a remote actuator that has not been confirmed off; HAL only issues its own `off` when debt exists — never turns off what it did not turn on | RFC-0018 §3g |
| **Non-reversible (`reversible`)** | Remote actuator where remaining on until human intervention could cause harm, or `off` does not restore exact previous state; default when `reversible = true` is omitted. Rule D5: non-reversible requires level ≥ L2 with readback | RFC-0018 §3f |
| **Proxy (`proxy mcp`, `proxy http`)** | Placing safety core in front of an existing MCP server or HTTP API: all calls pass gate before reaching destination. Effective only when proxy is the sole path to destination | `docs/architecture/vi/16-ecosystem-landscape.md` §4 · TSK-I2c-14, I2c-15 |
| **Plugin compliance test suite · NeuroEdge-gated** | `neuroedge conformance <package>`: tests by plugin type; passing grants "NeuroEdge-gated" badge in community index — free, non-certified | TSK-I2c-12 · TSK-P2-06 |
| **Hardware kit** | A template `neuroedge new --template <kit>` including BOM, wiring diagrams for Pi 5 and ESP32-S3, locked gates, golden traces, and "out-of-the-box to live run" guide. Five kits: `villa-concierge`, `home-voice`, `factory-monitor`, `gate-camera`, `blinds` | `docs/user/kit-phan-cung.md` · TSK-I2b-01, I2b-02 |
| **`neuroedge add`** | Quick scaffold command in an agent project: generates `@action` + gate + bidirectional tests + `[requires]` for a primitive; never overwrites existing files | `CHANGELOG.md` §2.3 · TSK-I2b-04 |
| **Fail-closed / fail-open** | When gate cannot be evaluated — error, timeout, or network loss without working local grammar fallback (Q-14) — block (default) / allow (only when gate explicitly declares `fail: open`) | `docs/spec/core_contracts.md` Appendix B.4 |
| **Action Contract** | Mandatory binding between physical action and its gate: HAL never executes any action that has not passed gate | PRD §5.1 |
