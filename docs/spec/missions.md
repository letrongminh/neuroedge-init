## 1. Introduction

### 1.1 Purpose

Today a person asks for one action and the gate decides it. A mission is a standing order: *"keep
the fish tank between 25 and 28 °C, never stop the air pump unless I say so, tell me when something
drifts, and don't spend more than $2 a month on analysis."* This specification states how that
sentence becomes a **mission contract** a person approves in five lines, how the box keeps it day and
night without trusting the LLM, and how the whole thing is proven on simulation (G1) before it
touches a real tank. It is loop ① (build the contract) and loop ② (run it) of Q-72.

### 1.2 Scope

In scope, by block (the roadmap tasks in brackets):

1. **The contract** — `mission.v1`, compiling, tiers, conflicts, the approval card, drafting and
   amendments [I2d-04 → I2d-06].
2. **Conditional safety** — a `safe_state` per output that may be *on*, declared only in `board.v1`
   with an interlock, and the "alarm, summon a person" state [I2d-01 → I2d-03].
3. **The 24/7 runtime** — one long-lived box process, its clocks, schedule, detectors, budgets,
   proactive messages and failure branches, supervising the NeuroClaw brain [I2d-07 → I2d-09].
4. **Chat approvals** — the box's own approval bot, pairing and signed approval records for `ask` and
   for amendments [I2d-11, I2d-12; RFC-0019 draft], and user-declared verification steps
   [I2d-20, I2d-21].
5. **Data and traces** — the box as the only exit for data, and segmented traces that replay a month
   [I2d-10, I2d-13, I2d-14].
6. **Proof on the fish tank** — the physics model (G1), the 24/7 run on Linux (G2), `lab doctor`, the
   Lab loop for contracts, and acceptance A15 → A22 [I2d-15 → I2d-19].

Out of scope: the brain's own conversation, memory, LLM calls and report wording (NeuroClaw,
`deployment_profiles.md` §2.2); mesh and multi-home (FR-AGT-11, Q-74); cloud brain (FR-AGT-10);
roles (FR-CH-07); phone-signed approvals (FR-CH-08); reflex-tier terms on the chip, which wait for a
`NETR` RFC (MS-CP-04); Slack and Zalo (FR-CH-01, P1); the optional relay (FR-EGR-05, P1).

### 1.3 Definitions

| Term | Meaning |
|:---|:---|
| **Mission contract** | A versioned data file, `missions/<name>@<version>.yaml`, valid against `schemas/mission.v1.json` (RFC, TSK-I2d-04): the devices, actions and gates it uses, and its terms. Not code. |
| **Term** | One rule of a contract: *permit*, *forbid*, *rate*, *window*, *obligation*, *expiry*, *destination*, *detector*, *budget*. |
| **Tier** | Where a term is enforced: **reflex** (on a device with `ne_gate`, ms, survives network loss), **skill** (the box runtime, s), **deliberation** (the brain, s–min). Each term gets the lowest tier able to enforce it (FR-MSN-10). |
| **Obligation** | The only "must" a contract can say: *"X beyond threshold for longer than T ⇒ Y goes to its safe state (or alarm) and the owner is told"*, every quantity bounded (FR-MSN-05). |
| **Approval card** | The ≤ 5-line summary of a contract or an amendment, generated by the compiler from the structured diff, never by an LLM (FR-MSN-12). |
| **Lock** | A contract version is locked when a person approved its digest: locally (CLI, page) or by a verified approval record in chat. `missions.lock` holds digest, approver, channel and time; only the box writes it, only after such an approval (MS-AP-05). |
| **Detector** | Deterministic code over sensor history — threshold, slope, flatline, oscillation — that raises an event; the brain is woken only by such events or by scheduled summaries (FR-AGT-04). |
| **Runtime** | `neuroedge agent run`: the box's long-lived process holding HAL, gates, contracts, schedule, detectors, approvals, egress and traces (FR-AGT-01). |
| **Brain** | NeuroClaw (Q-78, Q-83): untrusted, holds LLM keys, reaches the box only through MCP, never approves. |
| **G1 … G4** | Proof tiers of PRD §13: G1 physics model on `sim`, G2 Linux gpio-sim, G3 ESP32-S3 on QEMU, G4 Home Assistant / ESPHome host. |

## 2. Overall description

### 2.1 Product perspective

```
 person: "keep the tank 25–28 °C …"        brain (NeuroClaw, untrusted)         box (trusted, this repo)
 ─────────────────────────────────         ───────────────────────────          ────────────────────────
             chat / MCP client ──────────► drafts missions/…-draft.yaml ──MCP──► mission check: schema, compile,
                                           asks back for missing values          conflicts, approval card ≤ 5 lines
             ◄──────────── card + approval request (box's own bot) ─────────────┤
             "Đồng ý" (button, id) ─────────────────────────────────────────────► verify record → missions.lock
                                                                                │
                                                                       agent run: gates + envelopes + watchdogs
                                                                       schedule · detectors ──event──► brain
                                                                       urgent alerts (templates, no LLM)
                                                                       egress gate · segmented traces
```

### 2.2 Code boundary

New units in `python/neuroedge/`: `mission/` (model, compiler, conflicts, card, amendments, lock),
`agent/` (runtime, clocks, scheduler, detectors, budgets, alerts, supervision), `channels/` (the box's
approval bot), `egress/`. `mission/` may import `engine`, `hal` (boards), `errors`, `paths`;
`channels/` never imports `hal` (FR-CH-01); the brain is a separate repository. Conditional safety
changes `hal/`, `engine/`, `schemas/board.v1.json` and the C walker (`targets/esp32s3/`).

### 2.3 User classes

| Class | Uses |
|:---|:---|
| Home owner (family, Q-85) | Says what they want in chat; reads the card; approves; receives reports and alerts |
| Maker | Writes or reviews contracts with an MCP client (Lab); ships one in a Blueprint |
| Safety reviewer | Reads contracts, cards, `missions.lock`, traces; replays a month |
| Developer of NeuroEdge | Builds against G1 and G2 scenarios |

### 2.4 Constraints

1. **A contract only tightens.** Every action still goes through its locked gate; a term can narrow,
   never widen (FR-MSN-02, FR-MSN-03).
2. **Safety never lives in the brain.** No safety term is placed at deliberation tier (FR-MSN-10);
   losing the brain, the network or the LLM budget stops analysis only (NFR-REL-05).
3. **Only a person locks and approves** — never the brain, an MCP client, a chat group or an
   unpaired account (FR-CH-05, FR-AGT-09, Q-71).
4. **One clock rule.** Durations, deadlines and watchdogs use the monotonic clock; wall clock is a
   fact that can be `unsynced` (FR-MSN-04).
5. **RFC first** for `mission.v1`, conditional safety (`board.v1`, walker), `trace.v1` segments and
   events, the `chat:<id>` source, data flows, verification steps (CONTRIBUTING.md §3).
6. **Open with transparency** (Q-73): user-chosen verification and flows are allowed and labelled,
   not forbidden; the three invariants of CHANGELOG §3.3 stand.

### 2.5 Assumptions and dependencies

- Profile A install, pairing, MCP over mTLS and the brain's isolation exist (Q-83, done); the box's
  approval bot and signed records are RFC-0019 (draft).
- The fish tank agent (`fixtures/agents/aquarium`) is the reference agent; its `aerator_off` gate
  today asks the owner because the pump's safe state is *on* and `board.v1` cannot yet say so.
- Lab tools of `lab_mcp.md` are designed, not built; I2d-18 builds the contract part of them.

## 3. Specific requirements

Verification methods: **T** test, **I** inspection, **A** analysis, **D** demonstration.

### 3.1 Contract format (MS-CT)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-CT-01 | A mission contract shall be a YAML file `missions/<name>@<version>.yaml` valid against `schemas/mission.v1.json`, naming `schema`, `name`, `version` (SemVer, `-draft` allowed only unlocked), the agent it belongs to, the actions it uses, and its terms; it shall contain no code and no expression language beyond the gate operators. | Same review path as gates: readable, diffable, data. | FR-MSN-01 | T |
| MS-CT-02 | Each action a contract names shall exist in the agent and point to a locked gate; a `-draft` gate or an action the agent lacks shall make the contract invalid (three-part error naming the action). | A contract groups proven rules, it does not replace them. | FR-MSN-01 | T |
| MS-CT-03 | The term kinds shall be exactly: `permit`, `forbid` (with argument bounds), `rate` (at most N per window, at most T continuously), `window` (wall-clock hours, days), `obligation` (MS-WD), `expiry`, `destination` (MS-EG), `detector` (MS-RT-05), `budget` (`llm` per period, `messages` per day). An unknown kind shall be refused. | A closed vocabulary is what makes a five-line card and a conflict check possible. | FR-MSN-02 → FR-MSN-09 | T |
| MS-CT-04 | A contract shall not declare `safe_state`, an interlock or an envelope wider than the board's; it reads them from `board.v1` (MS-SF). | Fail-safe direction belongs to the hardware description, reviewed once. | FR-MSN-07, A21 | T |
| MS-CT-05 | A contract with deliberation-tier terms (detectors that wake the brain, summaries) shall declare `budget.llm`; a contract without `budget.messages` gets the default of 5 non-urgent messages per day, shown on the card. | No unbounded bill, no message storm. | FR-MSN-09, NFR-COST-02 | T |
| MS-CT-06 | Parameters a contract leaves open (a threshold, quiet hours, a channel) shall be declared as `ask` parameters with type and range; a contract with an unanswered parameter shall not compile, and the error lists what to ask. Defaults are allowed only when a Blueprint declares them, and are shown on the card. | The brain asks back instead of guessing. | FR-MSN-13 | T |

### 3.2 Compiling and tiers (MS-CP)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-CP-01 | `neuroedge mission check <file>` shall compile a contract into: per action, the extra criteria it adds to the gate's `allow_when` (as a child gate that only tightens, checked by the existing inheritance rules, NE2003); per output pin, envelope tightening; per obligation, a watchdog; per term, its tier. Exit 0 compiled, 1 with three-part errors. | One compiler, reusing gate inheritance rather than a second policy engine. | FR-MSN-02, FR-MSN-03, FR-CLI-15 | T |
| MS-CP-02 | A `permit` broader than the action's gate, or a `rate` looser than the board envelope (`window_s`, `max_on_ms_per_window`, `min_interval_ms`, `max_continuous_ms`), shall be refused naming the term and the gate or envelope it would loosen. | Tighten only. | FR-MSN-02, FR-MSN-03 | T |
| MS-CP-03 | Compiling the same contract against the same agent and board twice shall give byte-identical output and the same digest (`engine/canonical.py`, RFC 8785) on any machine. | The digest is what a person approves. | FR-MSN-01, FR-MSN-12 | T |
| MS-CP-04 | Each term shall be assigned exactly one tier, the lowest able to enforce it. In this version terms compile to **skill** tier on `sim` and `linux`; **reflex** tier on the chip waits for the `NETR` RFC and is reported as `skill` with the line "reflex on the device: not yet". A device reached through Home Assistant or a remote actuator stops at skill tier and the card says so. | Honest tiers; no `NETR` change without its RFC. | FR-MSN-10, RFC-0018 | T |
| MS-CP-05 | A safety term (obligation, `forbid`, `rate`, `window` on an output) that can only be enforced at deliberation tier shall be refused. | Safety never depends on the LLM. | FR-MSN-10, NFR-REL-05 | T |
| MS-CP-06 | A `forbid` that matches a call shall BLOCK with a reason naming the term in its own words (e.g. *"cấm tắt sục khí cho yên tĩnh"*), recorded in the trace as `mission_term` with the contract digest. | The person sees which promise stopped it. | FR-MSN-02, A17 | T |

### 3.3 Conflicts (MS-CX)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-CX-01 | `mission check` shall refuse, before any approval is requested, a contract whose terms contradict each other (a `forbid` and a `permit` of the same action whose argument and time ranges overlap; a `window` that can never be satisfied; two obligations driving one output to different states) or contradict the board (`safe_state`, envelopes, interlocks), naming **both** terms. | A person is never asked to approve something impossible. | FR-MSN-11, A15 | T |
| MS-CX-02 | The conflict corpus `fixtures/missions/` shall be bidirectionally closed: one expected entry per file in `expected_errors.yaml`, one file per entry; CI fails on any file without an entry or a wrong term pair. | A15 is measured, not claimed. | FR-MSN-11, A15, CONTRIBUTING §3 | T |
| MS-CX-03 | Conflict checking shall be decidable by interval arithmetic over the closed term vocabulary (ranges, windows, rates); a contract the checker cannot decide shall be refused as `undecidable` naming the terms, never accepted. | Fail closed on the checker's own limits. | FR-MSN-11 | T |

### 3.4 Time (MS-CK)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-CK-01 | Durations, watchdog thresholds, approval deadlines, expiry periods, rates and schedules shall be measured on the monotonic clock; a wall-clock jump (NTP, manual set) shall change none of them. | A clock change must not stretch a safety timer. | FR-MSN-04, FR-AGT-03 | T |
| MS-CK-02 | The runtime shall inject a wall-clock fact (`local_time`, `weekday`) with a status `synced` / `unsynced` (no NTP or RTC since boot); `local_time` joins `RUNTIME_CRITERIA` so no caller can supply it (RFC with TSK-I2d-04). | Time windows read a trusted fact. | FR-MSN-04, FR-ACE-09 | T |
| MS-CK-03 | A `window` term shall treat `unsynced` as a missing fact: a command that leaves `safe_state` and depends on the window is BLOCKED; moving toward `safe_state` is never blocked (Q-62); the card and page show *"đồng hồ chưa đồng bộ"*. | Fail closed on time, fail safe on direction. | FR-MSN-04, Q-62 | T |
| MS-CK-04 | On expiry every permission of the contract is revoked, outputs it drives return to `safe_state`, and the owner gets exactly one message asking to renew; renewal is an amendment (MS-AP-04). | Nothing runs forever by default. | FR-MSN-08 | T |

### 3.5 Obligations and watchdogs (MS-WD)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-WD-01 | An obligation shall have exactly the form *sensor (or fact) beyond threshold for longer than T ⇒ output to `safe_state` or `alarm`, and notify*; threshold within the sensor's range, `T` between 1 s and 24 h, the output one the contract names. Any other form, or a missing bound, shall be refused. | Bounded, checkable obligations only. | FR-MSN-05 | T |
| MS-WD-02 | A watchdog that fires shall drive its output to `safe_state` without passing a gate (Q-62), or, when the output's state is `alarm`, hold it and send an urgent alert (MS-RT-07); the event is traced with the obligation, the readings and the monotonic duration. | Going to safety is never refused. | FR-MSN-05, Q-62, FR-GATE-04 | T |
| MS-WD-03 | A sensor that stops reporting (no reading within its `max_age_ms`) shall count as beyond threshold for an obligation that protects against it, and raise a `sensor_stale` detector event. | A dead probe must not look like a calm tank. | FR-MSN-05, FR-AGT-04 | T |
| MS-WD-04 | A stuck sensor read shall not delay any other watchdog or gate decision beyond its budget: sensor reads run with a timeout off the decision loop (`TODOS.md` #48). | One bad bus cannot freeze the house. | FR-AGT-03 | T |

### 3.6 Conditional safety (MS-SF)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-SF-01 | `board.v1` shall let every output pin and motion channel declare `safe_state` (`off` default, `on`, or `alarm`); `on` and `alarm` shall require an `interlock` entry naming the hardware that holds the state when the controller is gone (normally-closed relay, watchdog timer, mechanical thermostat), and the board shall be refused without it (RFC TSK-I2d-02). | The air pump's safe state is *on*; saying so must cost a hardware argument. | FR-ACE-03, FR-MSN-07, A21, Q-72 | T |
| MS-SF-02 | `board.v1` shall reject keys a reader does not understand inside `v1` before `safe_state` becomes conditional (`requires = [...]` must-understand list, RFC TSK-I2d-01), so an older reader cannot silently treat `on` as `off`. | Fixes `TODOS.md` #58 first. | FR-ACE-03, FR-HAL-02 | T |
| MS-SF-03 | Every place that today means "off" when it says "safe" — envelope expiry, `max_continuous_ms`, leases, remote-actuator auto-off L0–L3, the Q-62 gate exemption, the token ledger's close, the C walker — shall mean "the declared `safe_state`"; moving *away* from it is the direction that needs a gate. | One meaning of "safe" in Python and C. | FR-ACE-03, RFC-0018 | T |
| MS-SF-04 | A `safe_state` declared anywhere but `board.v1` (gate, contract, agent.toml, part) shall be refused at load. | One place, reviewed once. | A21, FR-MSN-07 | T |
| MS-SF-05 | A board with `safe_state = on` on `sim` shall carry the risk label `simulated_interlock` on every start, trace and card; `sim-virtual` shall never declare one. | Simulation cannot prove a hardware interlock. | Q-73, DP-COM-06 | T |
| MS-SF-06 | Each actuator line of the card shall carry "on failure:" with its `safe_state` from the board; any state other than `off` is always shown, never folded into "defaults". | The person sees what the device does when things break. | FR-MSN-07, FR-MSN-12 | T |

### 3.7 Approval, drafting and amendments (MS-AP)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-AP-01 | `neuroedge mission explain <file> [--against <locked>]` shall print the approval card: at most 5 lines of plain Vietnamese (English with `--lang en`), generated only from the compiled structured diff, each line tagged with its tier; it lists only non-default terms and always shows `safe_state ≠ off` actuators, new destinations, probabilistic terms and risk labels. Same input ⇒ same bytes. | A card a person reads, that an LLM cannot reword. | FR-MSN-12, R-15 | T |
| MS-AP-02 | A change that does not fit 5 lines shall not be sent to chat; the card says *"quá dài để duyệt qua chat — duyệt tại nhà"* and approval is local only (CLI or page, full diff shown). | Long changes need a full read. | FR-MSN-12 | T |
| MS-AP-03 | Drafting shall happen outside the box (brain or MCP client); the box offers read-only checking tools — `mission_check`, `mission_explain` over MCP and Lab — and one write tool, `mission_draft_write`, that writes only `missions/*-draft.yaml`. No tool exposed to the brain or an MCP client can lock, approve, or write `missions.lock`, gates or `digests.lock` (tool list pinned by a test). | Agents propose; people decide. | FR-MSN-13, FR-AGT-09, Q-71 | T |
| MS-AP-04 | Every change — new contract, amendment, renewal, a proposal from the brain — shall go draft → `mission check` → card → approval → lock; until locked it has no effect. An amendment that adds a destination or a data type shall be approvable only locally. | One pipeline; data permissions are never widened by a tap in chat. | FR-MSN-14 | T |
| MS-AP-05 | Locking shall write `missions.lock` (contract name, version, digest, approver identity, channel `local` or `chat:<id>`, monotonic and wall time) only after a local approval or a verified approval record (MS-CH-03) for exactly that digest; `agent run` shall refuse a contract whose digest is not in `missions.lock`. | The digest approved is the digest that runs. | FR-MSN-01, FR-CLI-15 | T |

### 3.8 Runtime (MS-RT)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-RT-01 | `neuroedge agent run` shall start one long-lived process holding HAL, gates, locked contracts, schedule, detectors, approval verification, egress and traces; installed by `install --profile full` as a service that restarts on failure and power loss, each restart a trace event; outputs fall to `safe_state` while it is down through on-device lease or envelope expiry. | 24/7 without a person keeping a terminal open. | FR-AGT-01, NFR-REL-06 | T |
| MS-RT-02 | The runtime shall supervise the brain: the brain connects over MCP as today (Profile A); if it dies, hangs (no heartbeat within 60 s) or is not installed, gates, watchdogs, detectors and urgent alerts continue, the owner gets *"phân tích tạm ngưng"* once, and the brain's service is restarted with back-off. | Losing the brain loses analysis, nothing else. | FR-AGT-07, NFR-REL-05, Q-83 | T |
| MS-RT-03 | The scheduler shall run periodic sensor polling, contract expiry, summaries and detector evaluation on the monotonic clock, building on the N6 trigger rules of `lab_mcp.md` (debounce, rate ceiling, non-human origin); a call it makes has source `schedule` and is gated like any other. | Scheduled actions are not privileged. | FR-AGT-03, FR-ACE-09 | T |
| MS-RT-04 | No tool the runtime exposes to the brain shall write gates, `digests.lock`, `board.v1`, contracts other than drafts, or `missions.lock`; the list is pinned by a test. | Agent does not build, does not lock. | FR-AGT-09 | T |
| MS-RT-05 | Detectors shall be declared in the contract (or a Blueprint) from a closed set — `threshold`, `slope` (over N samples or days), `flatline`, `oscillation`, `sensor_stale` — with bounded parameters, computed in the box from sensor history kept for their longest window, each firing a traced `detector` event that replay reproduces. | Deterministic first, LLM second. | FR-AGT-04 | T |
| MS-RT-06 | The brain shall be woken only by a detector event, a scheduled summary or a person's message; the box counts wake-ups per period and stops scheduled ones at the contract's `budget.llm` expressed as a wake-up cap derived from the brain's reported `cost_usd` (unmetered ⇒ the configured unit price; neither ⇒ refused at check). On reaching it the owner gets *"đã hết ngân sách phân tích kỳ này"* once; the brain keeps its own `llm_budget` as a second ceiling (Q-83). | The box can cap what it asks for even though it cannot see the LLM bill. | FR-AGT-05, FR-MSN-09, NFR-COST-01, Q-83 | T |
| MS-RT-07 | Urgent alerts (a watchdog fired, `alarm`, a sensor gone, a budget reached, expiry) shall be sent by the box's own bot from fixed Vietnamese templates with no LLM, never batched or held by the message budget; routine messages from the brain beyond `budget.messages` are rolled into the next summary. | The alarm reaches the person even with no brain. | FR-AGT-06, NFR-COST-02, R-11 | T |
| MS-RT-08 | Each failure branch — brain dead, brain hung, chat channel down (bounded queue of 100, local page alerts, original timestamps kept), budget reached, approval expired, power lost — shall have a G1 or G2 scenario whose expected outcome is recorded; in none does an output leave `safe_state` or a recorded BLOCK go missing. | Failure behaviour is specified by tests. | FR-AGT-07 | T |

### 3.9 Chat approvals and verification steps (MS-CH)

| ID | Requirement | Rationale | Source | Verification |
|:---|:---|:---|:---|:---|
| MS-CH-01 | `neuroedge chat connect telegram` shall store the box's own bot token in the runtime's configuration (mode 0600, never printed, never given to the brain); `neuroedge chat pair` shall run only on the home machine and show the pairing code on-site; groups never pair. | The approval channel is the box's, not the brain's. | FR-CLI-14, FR-CH-03, DP-A-06 | T |

| MS-CH-04 | Approval records shall serve both an `ask` of a gate (entering the RFC-0006 confirmation path) and a contract lock (MS-AP-05); at most 4 requests pending per box (DP-COM-09); an expired one is a no. | One mechanism for both kinds of consent. | FR-ACE-10, FR-CH-04, DP-COM-09 | T |

## 4. Interfaces

### 4.1 `mission.v1` (illustrative; the RFC of TSK-I2d-04 writes the schema)

```yaml
schema:  neuroedge.mission/v1
name:    be-ca
version: 1.0.0
agent:   aquarium
actions: [heater_on, heater_off, aerator_on, aerator_off, light]

terms:
  - forbid:     aerator_off            # only the owner, through the gate's own ask
    words:      "cấm tắt sục khí, trừ khi chủ nhà đồng ý"
  - rate:       heater_on
    max_continuous: 2h
  - window:     light
    allow:      "07:00-22:00"
  - obligation: { when: { sensor: temperature, gt: 30 }, for: 10m, then: { output: heater, to: safe_state }, notify: urgent }
  - obligation: { when: { sensor: temperature, lt: 22 }, for: 30m, then: { output: heater, to: alarm }, notify: urgent }
  - detector:   { kind: slope, sensor: oxygen, falling: 3d, notify: summary }
  - destination: { to: telegram, data: [text] }
  - destination: { to: llm, data: [text, readings] }
  - expiry:     90d
  - budget:     { llm: "2 USD / month", messages: "5 / day" }

parameters:
  - { name: warm_from, type: number, unit: C, range: [26, 32], ask: "Nước ấm từ bao nhiêu độ?" }
```

### 4.2 Approval card (example)

```
Bể cá 1.0.0 — 5 điều, chạy tại hộp (skill), chưa có phản xạ trên thiết bị
• Sục khí: không ai tắt được, trừ chủ nhà đồng ý · khi lỗi: BẬT (rơ-le thường đóng)
• Sưởi: tự tắt nếu nước > 30 °C quá 10 phút, báo ngay
• Đèn: chỉ 07:00–22:00 · Báo cáo: tối đa 5 tin/ngày, phân tích ≤ $2/tháng
• Dữ liệu: chữ và số đo gửi Telegram và LLM; không ảnh · Hết hạn sau 90 ngày
```

### 4.3 Command line

```
neuroedge mission check <file>                 # 0 compiled · 1 refused (schema, conflict, loosening)
neuroedge mission explain <file> [--against <locked>] [--lang en]
neuroedge mission lock <file>                  # local approval: shows the full diff, asks y/N
neuroedge agent run [--agent dir]              # refuses an unlocked contract
neuroedge chat connect telegram · neuroedge chat pair
neuroedge lab doctor [--agent dir]
```

Command names are final when the `mission.v1` RFC is signed (FR-CLI-15).

## 7. Decisions this specification takes (Q-87, product owner, 2026-10-16)

| ID | Decision | Why | Alternative |
|:---|:---|:---|:---|
| MS-D-01 | The LLM budget is held twice: the box caps how often it wakes the brain, from the cost the brain reports; NeuroClaw keeps its own `llm_budget` (MS-RT-06) | Under Q-83 the brain calls the LLM, so the box cannot meter the bill; it can meter what it asks for | Box only displays the budget and trusts NeuroClaw |
| MS-D-02 | Version 1 compiles every term to skill tier on the box; reflex-tier terms on the chip wait for a `NETR` RFC, and the card says "reflex on the device: not yet" (MS-CP-04) | Reflex tier changes `NETR` (RFC), and the chip does not drive pins yet (TSK-S4-01) | Write the `NETR` RFC inside I2d |
| MS-D-03 | Contracts are YAML like gates; locking writes `missions.lock` after a local or chat approval of the exact digest (MS-CT-01, MS-AP-05) | Same review path as gates; a family locks from chat, a maker from the CLI or a PR | Lock only through a PR, like gates |
| MS-D-04 | `safe_state = on` on `sim` is allowed with `risk=simulated_interlock` (MS-SF-05) | The fish tank's pump must be provable on G1; simulation cannot prove hardware | Forbid `on` on `sim`, keep today's `ask` workaround until G3/G4 |
