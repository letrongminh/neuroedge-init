# Public surface — Python API (`import neuroedge`) and CLI (`neuroedge`)

**Trạng thái:** canonical (TSK-I6-06, Q-63); deprecation policy (§5), reading of `0.x` (§3), public `SimSession` (§2.1), and CLI contract (§6) decided in Q-64. PRD §10.3 promises SemVer for the `neuroedge` package ("changes to the public API surface or CLI")
but does not define what is public; this document defines it, for the Python API (§1–§4) and for the CLI (§6).
**Source code:** `python/neuroedge/__init__.py` (`__all__`) · `python/neuroedge/sim/serve.py` (`serve_mcp`) · `python/neuroedge/cli/main.py` (command tree).
**Pinned tests:** `python/tests/test_public_api.py` (Python API) · `python/tests/test_cli_contract.py` (CLI).

This document is the **single place** defining what belongs to the public Python API and CLI, and what SemVer promises about them.
Other documents link here, not copy (CONTRIBUTING §8.1). Keywords **MUST**, **MUST NOT**,
**SHOULD** carry their RFC 2119 meanings. The list of names lives in `neuroedge.__all__`; the table in §2 only explains
each group, and tests enforce that every name is present there.

## 1. What is public

**Public is every name in `neuroedge.__all__`, and only them.** An integrating project only needs
`import neuroedge`: instantiate a HAL, load gates, call `dispatch`, start MCP server (I6 exit criterion 9).

| In public surface | Outside public surface |
|:---|:---|
| Names in `__all__`, accessed as `neuroedge.<name>` | All submodules: `neuroedge.engine`, `neuroedge.hal.sim`, `neuroedge.sim`, `neuroedge.cli`… — usable, but **unpromised** |
| Call signatures of those names: parameter names, order, required vs optional | Names starting with `_`, any attributes or methods not mentioned in docstrings or specifications |
| Behaviors described by docstrings and referenced specifications | Test double injection parameters (`gpiod`, `sounddevice` of HAL) |
| Error classes and the **`NE…` codes** they raise (PRD Appendix B) | Text phrasing of `why` and `how` (may be improved; error classes and codes do not drift — CONTRIBUTING §3) |
| Names and classes of errors in `__all__`; three attributes `where`, `why`, `how`, and `code` of `NeuroEdgeError` | Key ordering, `repr`, performance, number of events in traces |

Public by **name**, not by **location**: `neuroedge.SimHAL` is promised; `neuroedge.hal.sim.SimHAL`
runs today but a future release may move it. Code generated by `neuroedge new` and sample agents
only import public names via `from neuroedge import …`.

**Intentional exception: two modules public by location** (RFC-0016 §3e, TSK-I2c-07). `neuroedge.guard`
(standalone safety core — [`extension_sdk.md`](extension_sdk.md) §1) and `neuroedge.sdk` (surface for
extensions — §2 of that document) are promised by path, each module having its own `__all__`. `neuroedge.guard`
shares the same stability level as `__all__` (`0.x`, §3; RFC-0016 §9.1); `neuroedge.sdk` has its own `SDK_VERSION`.
**`neuroedge.__all__` is unchanged**: `Guard` is not in it (RFC-0016 §9.2), use
`from neuroedge.guard import Guard`.

File format contracts do **not** belong to this document as they have separate versioning: gate schema, traces, `board.v1`,
`tool-call.v1`, `tool-result.v1`, `error.v1`, and error code registry `error-codes.v1` (RFC-0015)
(PRD §10.3, `schemas/`, `CONTRIBUTING.md` §3), and `NETR` binary layout (RFC-0003, RFC-0009). The
"or CLI" clause of PRD §10.3 is defined in §6.

## 2. Current surface

| Group | Names | Used for |
|:---|:---|:---|
| Version | `__version__` | Package version string |
| HAL | `HardwareAbstractionLayer`, `SimHAL`, `LinuxHAL`, `PinAssertion`, `BoardProfile`, `load_board_by_id`, `digital`, `motion` | Instantiate HAL for `sim` or `linux`, assert pin states, read board profiles; `digital.out(pin)` is how `@action` bodies control pins, `digital.input(pin).level()` is how it reads the logic level of a declared input pin (RFC-0007 §3a; requires no token, read failure ⇒ `PerceptionUnavailableError`). `motion.motor(channel, speed=…, ramp_ms=…)`, `motion.servo(channel, target=…)`, and `motion.stop(channel)` control declared motion channels (RFC-0011 §3b): commands run only within the lease duration of the verdict, renewed by a new pass through gates, expiration ⇒ channel safe state; `stop` is a failsafe command, never blocked. `LinuxHAL` requires extra `linux` (`gpiod`) **when instantiated**, not upon `import neuroedge` |

All error classes in `errors.py` **MUST** be in `__all__` (pinned by test): integrators catch errors by class,
so an unexported error class cannot be caught.

### 2.1 `SimSession` and `Turn`: only these members are promised

`SimSession` is where an agent is assembled (`docs/architecture/03-component-host-c4l3.md` §2), making this
class large and subject to evolution. The SemVer promise covers **only** members used by `neuroedge new` code and documentation;
everything else on `SimSession` and `Turn` is outside the promise (§1), even if not prefixed with `_`.

| Name | Promised |
|:---|:---|
| `SimSession.load(agent_toml="agent.toml", *, board_id, facts, registry, clock, events, slow, target, target_options)` | Exactly these nine parameters, names, order, and defaults; raises `BuildFailed` when agent does not match board, `BoardCapabilityError` when `linux` cannot run agent (`load` docstring) |
| `await session.handle(text)` | Runs a typed utterance through grammar, `c.do()`, and gates; returns a `Turn`. Keyword arguments of `handle` (`heard_after_ms`, `spoken`, `answer_to`) are **not** promised |
| `session.hal` | Session HAL (`session.hal.pin(name)` asserts pin states) |
| `session.set_sensor(sensor, value)` | Sets simulated sensor value returned by HAL |
| `session.trace()` | Validated `trace.v1` trace of session up to this point |
| `session.events.of_type(type)` | Recorded events filtered by type |
| `Turn.recognised`, `Turn.allowed` | `recognised`: grammar recognized command; `allowed`: action executed because gate permitted |
| `Turn.result` | `ActionResult` of action, or `None` if no action; `result.blocked`, `result.gate` (a `GateResult`) |
| `Turn.reply_source` | Reply source: string or `None` (specific string values are not promised) |
| `Turn.confirmation` | `None` when device does not ask user; non-`None` when question awaits response |

Tests in `neuroedge new` code only use members in the table above (plus files of the project itself, such as
`agent.toml`); reading `session.grammar`, `session.sensor_facts`, or `session.gate_facts` relies on internals.

## 3. SemVer policy

The `neuroedge` package follows [SemVer 2.0.0](https://semver.org/lang/vi/) on the surface in §1 and CLI contract in §6. For version
`MAJOR.MINOR.PATCH`:

| Change | Increment |
|:---|:---|
| Remove or rename a name in `__all__`; change signature breaking old calls (drop parameter, add **required** parameter, reorder positional parameters); change error class or `NE…` code raised in a scenario; change described behavior | **MAJOR** |
| Add a name to `__all__`; add **optional** parameter with default preserving old behavior; add new error class | **MINOR** |
| Bug fixes without changing described behavior; improvements to `why`/`how` wording; internal changes | **PATCH** |

Two product-specific invariants:

- **Safety is never compromised for "compatibility".** A change causing gates to block more, or closing a
  loophole bypassing gates, is permitted in a MINOR or PATCH release even if existing code relied on that behavior (invariant
  `CHANGELOG.md` §3.3 #2: fail-closed). Documented clearly in `CHANGELOG.md`.
- **Every change to `__all__` is an explicit decision.** `test_public_api.py` pins the list: adding or removing
  a name turns CI red until the pinned list, §2 table, and `CHANGELOG.md` entry are updated in the same PR.

**Meaning of `0.x`.** SemVer permits `0.y.z` to change at any time. NeuroEdge **tightens** that statement:
in `0.x`, MINOR acts as MAJOR — breaking changes happen only in MINOR releases (`0.y` → `0.y+1`),
never in PATCH releases, and still follow §5 rules. The full promise of §3 begins at `v1.0`.
*(Q-64.)*

## 4. Starting MCP server from Python

```python
import neuroedge

neuroedge.serve_mcp("agent.toml")            # blocks until client closes stdin
```

`serve_mcp` performs the exact work of `neuroedge mcp serve` (without `--ui`), as both share the same serving
loop (`sim/serve.py::run_stdio`), not two code paths:

- Every `@action` of the agent is a tool; every `tools/call` takes **a single path** to hardware — schema check,
  `c.do()`, gate, single-use token, HAL (`docs/spec/tool_calling.md` §2). There are no parameters to
  disable gates or self-declare `call_source`: connection source is `mcp` (§5 of that spec).
- `trace_out` records session trace upon exit; user utterances are **hashed** unless `raw=True` (which emits a
  `UserWarning` and records `metadata.anonymized = false`, as with `--raw`). Default preserves NFR-PRIV-03.
- `target="linux"` controls physical pins: process exits via cleanup handler upon receiving SIGTERM or SIGHUP,
  all pins returning to low/off state (like `mcp serve --target linux`).
- **`serve_mcp` owns the process.** Two exits terminate the entire calling process via `os._exit`, after
  cleanup (writing traces, releasing all pins): no client sending `initialize` within `init_timeout` seconds (default
  30; `0` waits forever), and SIGTERM/SIGHUP when `target="linux"`. Reason: MCP SDK stdin read thread
  cannot be cancelled, so only process exit can reclaim it. Call `serve_mcp` in a dedicated process,
  not in a process with other ongoing tasks.
- stdout belongs to the protocol; everything intended for human readers goes to stderr. If MCP SDK is missing (extra `mcp`),
  `serve_mcp` raises `NeuroEdgeError` with installation instructions before building anything.

Synchronous function running its own event loop: do not call directly from a coroutine. Users requiring the
`--ui` interface should use the CLI: that web page is not part of the public Python surface.
Similarly, network endpoints for MCP server (`neuroedge mcp serve --http`: Streamable HTTP, mTLS, OAuth 2.1 token;
`docs/spec/tool_calling.md` §8.1) are CLI responsibilities, **not yet** part of the public Python surface: `serve_mcp`
serves only via stdio, and provides no parameters to open network ports.

## 5. Deprecation policy (Q-64)

Public surface does not disappear abruptly:

1. A name (or parameter, or behavior) scheduled for removal **MUST** be marked *deprecated* in a
   **MINOR** release: it continues running as before, but emits a `DeprecationWarning` stating replacement name and release that will remove it,
   and `CHANGELOG.md` records it under *Changed*.
2. It **MUST** remain functional for at least **one full MINOR release** after deprecation (if marked in `1.4`,
   it remains in `1.5`; removed in `2.0`). Only **MAJOR** releases may remove it entirely.
3. In `0.x`: same rules apply, with MINOR taking the place of MAJOR (§3) — deprecated in `0.y`, removed at earliest in `0.y+2`.
4. The sole exception is security vulnerabilities: removed immediately in a PATCH release, with explanation in changelog.
5. Warnings use `warnings.warn(..., DeprecationWarning, stacklevel=2)`, pointing to caller's line.
   Code in repo **MUST NOT** rely on deprecated names.

*No names are currently deprecated.* When deprecations occur, this section will receive a table: name, deprecated in, removed in, replacement name.

## 6. CLI contract

CLI is `neuroedge <command> …` (identical to `python -m neuroedge`). Governed by same SemVer policy (§3) and deprecation
rules (§5, Q-64) as Python API; in `0.x`, MINOR acts as MAJOR.

| Promised | Not promised |
|:---|:---|
| Command and subcommand names (`gate lint`, `mcp serve`…) | Human-readable text printed to stdout and stderr: wording, colors, line order, tables, boxes |
| Flag and option names (including short form `-t`), their semantics, whether flags take values, repeatability | Execution duration, table widths, `Examples:` block of `--help` |
| Required arguments and order of positional arguments | Default output paths for files written when `--out` is omitted |
| **Exit codes** — table in `docs/reference/cli.md` §3 (`0` pass, `1` fail, `2` not implemented), not duplicated here | Diagnostic text in `why`/`how` (`NE…` codes are promised, §1) |
| Machine-readable output: `--json`, `--openai`, and command output files (separate versioned schemas — `schemas/`, PRD §10.3; not repeated here) | |

**`add` command family (TSK-I2b-04, FR-DX-08).** Promises five subcommands `add action`, `add sensor`, `add device`,
`add gate`, each taking a name as required argument, and `add part` (Q-84, `virtual_parts.md` VP-PT-07: optional
kind and name arguments, `--list`, `--sensor`, `--drives`); flags `--primitive`, `--pin`, `--channel`,
`--source`, `--label`, `--device`, `--register`, `--width`, `--fact`, `--board`, and `--agent` as captured in
`test_cli_contract.py`. Behavioral contract: commands run only within projects containing `agent.toml`; **never overwrite**
an existing file, `[gates]` key, action name, or command name (rejected with three-part error, exit code `1`, writes nothing);
output is dry-run built on a copy before writing to project. Printed text is not promised. `new --board sim-virtual` (VP-VB-09) starts a project on the virtual board.

**`guard`, `proxy`, `plugin` command family (TSK-I2c-14, FR-EXT-06).** Promises `guard init` (required flag `--mcp`, `--dir`, `--name`, `--env-from`, `--header-env`; never overwrites files),
`proxy mcp` (`--config`, `--trace-out`, `--desktop-config`, `--write`, `--config-path`, `--name`; stdio only), `proxy http` (`--config`, `--trace-out`; loopback only — TSK-I2c-15, `extension_sdk.md` §5; `guard init` accepts `--http` and `--route` alongside `--mcp`, mutually exclusive; `--allow-lan-http` writes `allow_lan_http` key for pure HTTP devices on home network — `extension_sdk.md` §4.1a), and `plugin doctor` (`--config`, `--json`; exit code `1` on warnings). Syntax `guard.toml`/`[proxy.mcp]`
and behavior: [`extension_sdk.md`](extension_sdk.md) §4. Printed text is not promised.

**`plugin list` and `conformance` (TSK-I2c-16; RFC-0016 §3d, §3g).** Promises `plugin list` (`--json`: list of `{kind, name, distribution, version, value}`; imports no packages, exit code `0`) and
`conformance <distribution>` (`--kind`, `--json`; exit code `0` when all checks `pass`, `1` when any `fail`/`unverifiable` or no entry points found or uninstalled, `2` when plugin kind cannot be checked).
No command or flag **enables** a plugin into a session: enablement lives in `[plugins] enable` of committed files (`test_no_cli_flag_enables_a_plugin`). `--json` report and checks: [`extension_sdk.md`](extension_sdk.md) §8.

**Versioning rules for CLI:**

| Change | Increment |
|:---|:---|
| Rename or drop a command, flag, or option; change semantics of an exit code; change `--json`/`--openai` shape breaking old consumers; turn optional argument or flag into required; turn flag into value-bearing option | **MAJOR** (in `0.x`: MINOR) |
| Add a command or **optional** flag; add keys to `--json` that old consumers can safely ignore | **MINOR** |
| Command (or `--target`) transitioning from code `2` ("not implemented") to `0` or `1` | **MINOR**, not a breaking change: code `2` promises "not yet", not "never" |
| Text, color, table adjustments; bug fixes | **PATCH** |

When renaming or removing, the old name **MUST** remain functional as a hidden alias (`hidden=True`) emitting a deprecation warning
to stderr for exactly one full MINOR release (§5). Safety remains prioritized: a command whose former behavior allowed
what gates should block is fixed immediately, under §5 exception.

**Enforcement.** `test_cli_contract.py` reads Typer command tree and compares against a line-by-line snapshot per command:
full name, arguments in order, flags (with `=` if value-bearing, `!` if required). Adding, removing, or modifying a
command or flag turns CI red until snapshot, SemVer section above, and `CHANGELOG.md` are updated in the same PR. Exit codes
and `--json` are verified by individual command tests, not this snapshot.
